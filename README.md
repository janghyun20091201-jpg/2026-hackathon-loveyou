# Part A. 웹 코드 (js 6개)

웨어러블(ESP32)과 블루투스(BLE)로 연결해서 압박 데이터를 받고, 노트북/휴대폰 카메라로 환자의 압박 위치와 구조자의 팔 자세를 인식해 실시간으로 피드백하는 웹 프로그램입니다.

## A-1. 파일별 역할

| 파일 | 역할 | 주요 내용 |
|---|---|---|
| `app.js` | **화면 흐름 컨트롤러 (메인)** | 화면 전환(`go`), 기기 연결 화면, 3초 카운트다운, 실시간 연습 화면, 실전 모드, 결과 리포트 표시 |
| `config.js` | 설정 | CPR 판정 기준값, 점수 가중치, 블루투스 UUID, 피드백 문구 |
| `device.js` | 기기 통신 | Web Bluetooth로 ESP32 연결, 데이터 줄 단위로 해석, `START`/`STOP`/`BPM` 명령 전송 |
| `pose.js` | 카메라 자세 인식 | Google MediaPipe Pose(33개 관절점)로 환자 압박 위치·구조자 팔꿈치 각도 계산, 화면에 그리기 |
| `session.js` | 판정 · 점수 | 압박 1회마다 기록, 실시간 피드백 판정, 종합 점수·등급·가장 부족한 항목 계산 |
| `report.js` | 결과 그래프 | 압박 깊이 그래프(5~6cm 적정 구간 표시), 이완 잔여 압력 그래프 |

파일 연결 관계:
```
app.js ─┬─ config.js   (기준값·문구)
        ├─ device.js   (ESP32와 블루투스 통신)
        ├─ pose.js     (카메라 → 압박 위치·팔 각도)
        ├─ session.js  (판정·점수)
        └─ report.js   (결과 그래프)
```

## A-2. 화면 흐름 (`app.js`)

**연습 모드**
```
홈 → ① 기기 연결 · 환자 촬영 → [시작] → 3초 카운트다운 → ② 실시간 연습 → [종료] → ③ 결과 리포트
```
1. **기기 연결 · 환자 촬영** : 블루투스로 웨어러블을 연결하고, 카메라로 환자(마네킹)를 촬영해 압박 위치를 빨간 원으로 표시합니다. 카메라 방향(옆에서 / 위에서)과 전면·후면 카메라를 고를 수 있습니다.
2. **실시간 연습** : '시작'을 누르면 3초 카운트다운 후 기기에 `BPM,110`과 `START`를 보내 측정을 시작합니다. 속도·깊이 게이지, 손바닥 압력 그래프, 손목 기울기, 피드백 문구, 작은 카메라 화면(팔 자세)이 실시간으로 바뀝니다.
3. **결과 리포트** : 종합 점수와 등급, 가장 많이 틀린 항목, 항목별 적정 비율, 깊이·잔여 압력 그래프를 보여줍니다.

**실전 모드**
```
홈 → [실전 모드] → (기기 미연결 시 연결 화면) → 연결 즉시 박자 안내 시작 → [종료] → 홈
```
- 실제 상황에서는 카메라 설치가 어렵기 때문에 자세 교정(카메라)과 결과 리포트를 생략합니다.
- 화면에는 압박 횟수, 경과 시간, 피드백 문구, 속도·깊이·잔여 압력·기울기 칸, 2분 교대 알림만 표시하고, 종료하면 총 압박 횟수를 알려줍니다.

## A-3. 보고서 「주요 알고리즘」과 코드 위치

| 보고서 단계 | 코드 위치 |
|---|---|
| 1. 웹 연결 (BLE) | `device.js` → `connectBLE()` |
| 2. 환자 촬영 | `pose.js` → `start()`, `app.js` → `enableCamera()` |
| 3. 압박 위치 안내 | `pose.js` → `chestTarget()` : 양 어깨(11, 12)와 골반 중점(23, 24)이 이루는 삼각형의 무게중심 |
| 4. '시작' → 3초 카운트다운 | `app.js` → `enterPractice()`, `countdown()` |
| 5. 박자 안내 (110 BPM) | `app.js` → 기기에 `BPM,110` 전송 (소리는 ESP32 부저가 냄) |
| 6. 압박 측정 | `device.js` → ESP32가 보낸 깊이·속도·압력·기울기 값 수신 |
| 7. 팔 자세 판정 | `pose.js` → `jointAngle()` : 어깨–팔꿈치–손목 각도, 160° 미만이면 굽은 팔 |
| 9. 웹 화면 경고 | `app.js` 게이지·피드백, `session.js` → `feedback()` (10초 중단 경고, 2분 교대 알림) |
| 10. 결과 리포트 | `session.js` → `summary()`, `report.js` 그래프 |

## A-4. 판정 기준과 점수 계산

**판정 기준** (`config.js` → `CONFIG.cpr`)

| 항목 | 기준 |
|---|---|
| 압박 속도 | 분당 100~120회 |
| 압박 깊이 | 5~6cm (최근 3회 평균으로 판정) |
| 이완 | 이완할 때 손바닥 잔여 압력 2.5kg 미만 |
| 손목 기울기 | 15° 이하 |
| 팔 자세 | 팔꿈치 각도 160° 이상 |
| 중단 경고 | 10초 이상 압박 없음 |
| 교대 알림 | 2분마다 |

**실시간 피드백 우선순위** (`session.js` → `feedback()`)
`중단 > 깊이(얕음/깊음) > 속도(느림/빠름) > 이완 > 기울기 > 팔 자세 > 좋음`
여러 문제가 동시에 있으면 가장 중요한 하나만 표시합니다.

**종합 점수** (`session.js` → `summary()`)
- 항목별로 "기준을 지킨 압박의 비율(%)"을 구합니다.
- 가중 평균: 깊이 30 · 속도 25 · 이완 20 · 팔 자세 15 · 기울기 10
  (카메라를 안 쓰는 등 측정 안 된 항목은 빼고 계산)
- 압박 중단 1번마다 5점 감점
- 등급: 90점 이상 우수 / 75점 이상 양호 / 60점 이상 보통 / 그 아래 연습 필요
- 가장 부족한 항목: 적정 비율이 가장 낮은 항목을 골라 고치는 방법과 함께 보여줌

## A-5. 카메라 자세 인식 (`pose.js`)

- **옆에서 볼 때 (노트북)** : 사람을 최대 2명 인식해서 몸통이 가로로 누운 사람은 환자, 팔이 잘 보이는 나머지 사람은 구조자로 구분합니다. 구조자의 두 팔 중 더 굽은 팔의 각도로 판정하고, 160° 이상이면 팔 선을 초록색, 미만이면 빨간색으로 그립니다.
- **위에서 볼 때 (휴대폰)** : 위를 보고 누운 사람 중 몸통이 가장 크게 보이는 사람을 환자로 고릅니다. 골반이 없는 상반신 마네킹은 코 → 어깨 중점 방향으로 압박 위치를 계산합니다.
- 모델은 GPU로 먼저 실행하고, 안 되면 CPU로 실행합니다.

## A-6. 기기와 주고받는 데이터 (`device.js`)

블루투스 Nordic UART Service(NUS)로 한 줄씩 문자열을 주고받습니다.

| 방향 | 형식 | 의미 |
|---|---|---|
| ESP32 → 웹 | `D,<깊이mm>,<압력kg×10>,<기울기°×10>` | 실시간 값 |
| ESP32 → 웹 | `C,<누적횟수>,<깊이mm>,<분당속도>,<이완%>,<최대압력>,<잔여압력>,<기울기>` | 압박 1회 완료 |
| 웹 → ESP32 | `START` / `STOP` | 측정 시작 / 종료 |
| 웹 → ESP32 | `BPM,110` | 부저 박자 설정 |

# Part B. ESP32 하드웨어 테스트 (`esp32_test.ino`)

골든밴드(팀 심장폭격기) CPR 손목 기기에 들어가는 부품이 제대로 연결되어 작동하는지 확인하는 테스트 코드입니다.
ESP32가 직접 와이파이를 만들고, 휴대폰이나 노트북으로 그 와이파이에 접속해서 웹페이지 버튼으로 부품을 하나씩 시험할 수 있습니다.

> Part A 웹 코드와는 별개의 프로그램입니다. Part A는 블루투스(BLE)로 기기와 통신하고, 이 테스트 코드는 ESP32가 만든 와이파이에 접속해서 사용합니다.

- 파일: `esp32_test.ino`
- 보드: ESP32 Dev Module
- 추가 라이브러리: 필요 없음 (ESP32 기본 `WiFi`, `WebServer`, `Wire`만 사용)

---

## 1. 접속 방법

| 항목 | 값 |
|---|---|
| 와이파이 이름 | **CPR-Test** |
| 비밀번호 | **12345678** |
| 접속 주소 | **http://192.168.4.1** |

1. ESP32에 전원을 연결합니다. (USB 또는 18650 배터리)
2. 휴대폰/노트북 와이파이 목록에서 **CPR-Test**를 선택하고 비밀번호 **12345678**을 입력합니다.
3. 브라우저(크롬, 사파리 등) 주소창에 **http://192.168.4.1** 을 입력합니다.

> 인터넷이 없는 와이파이라서 휴대폰에 "인터넷 연결 없음" 알림이 뜰 수 있습니다. 이때 **연결 유지**를 선택하면 됩니다.
> 주소는 `https`가 아니라 `http`로 입력해야 합니다.

---

## 2. 사이트에서 할 수 있는 것

| 구역 | 버튼 | 동작 |
|---|---|---|
| RGB | 빨강 | 빨간 LED 켜기 |
| | 초록 | 초록 LED 켜기 |
| | 노랑 | 빨강 + 초록을 동시에 켜서 노란색 표시 |
| | 끄기 | LED 끄기 |
| 부저 | 삐 (0.3초) | 부저를 2700Hz로 0.3초 울림 |
| MPU6050 | 실시간 보기 시작 / 정지 | 0.3초마다 가속도·각속도 값을 화면에 표시 |

- 버튼을 누르면 화면 위쪽 상태 줄에 결과가 표시됩니다. (예: `RGB → 빨강`, `부저 울림`)
- MPU6050 값의 의미
  - `ax ay az` : x·y·z축 가속도 (단위 g). 센서를 평평하게 두면 `az`가 약 1.00이 됩니다.
  - `gx gy gz` : x·y·z축 회전 속도 (단위 °/s). 가만히 두면 0 근처입니다.
- MPU 선이 빠져 있으면 `MPU 응답 없음 → SDA(27)·SCL(33)·VCC·GND 배선 확인`이 표시되고, 다시 꽂으면 자동으로 재연결됩니다.
- ESP32와 연결이 끊기면 `연결 끊김`이 표시됩니다.

## 3. 배선 (830홀 브레드보드 최종 배치 기준)

| 부품 | 부품 핀 | ESP32 핀 |
|---|---|---|
| 부저 | + | GPIO 25 |
| | − | GPIO 26 |
| MPU6050 | SDA | GPIO 27 |
| | SCL | GPIO 33 |
| | VCC / GND | 3V3 / GND |
| RGB LED 모듈 | R | GPIO 13 |
| | G | GPIO 12 |
| | B | 연결 안 함 |

부저의 −를 GND가 아닌 GPIO 26에 연결한 이유는, 두 핀에 전압을 번갈아 주면 부저 양 끝 전압 차가 2배가 되어 소리가 더 크게 나기 때문입니다.

## 4. 업로드 방법 (Arduino IDE)

1. 보드 매니저에서 **esp32 by Espressif Systems** 설치
2. 툴 → 보드: **ESP32 Dev Module**
3. 툴 → Upload Speed: **115200**
   (기본값 921600이면 `Unable to verify flash chip connection` 오류가 날 수 있음)
4. 업로드 후 시리얼 모니터(115200)를 열면 다음이 출력됩니다.
   ```
   MPU OK
   접속 주소: http://192.168.4.1
   ```

## 5. 코드 설명

### 전체 구조

```
esp32_test.ino
├─ 설정        와이파이 이름/비밀번호, 핀 번호
├─ PAGE        사이트 HTML (버튼 화면 + 자바스크립트)
├─ beep()      부저 울리기
├─ mpuInit()   MPU6050 깨우기
├─ mpuRead()   MPU6050 값 읽기
├─ handle...   사이트 요청 처리 (/, /rgb, /beep, /mpu)
├─ setup()     핀 초기화 → MPU 연결 → 와이파이 생성 → 웹서버 시작
└─ loop()      웹 요청 계속 처리
```

### 주요 부분

**① 웹페이지 (`PAGE`)**
사이트 HTML 전체를 코드 안에 문자열로 넣어 두었습니다(`PROGMEM`). 버튼을 누르면 자바스크립트 `fetch()`로 ESP32에 요청을 보내고, 응답 문장을 상태 줄에 표시합니다. MPU 실시간 보기는 `setInterval`로 0.3초마다 `/mpu`를 요청합니다.

**② 부저 (`beep`)**
원하는 주파수(hz)의 반주기마다 25번 핀과 26번 핀을 HIGH/LOW로 반대로 바꿔 소리를 냅니다. 소리가 끝나면 두 핀 모두 LOW로 꺼 둡니다.

**③ MPU6050 (`mpuInit`, `mpuRead`)**
라이브러리 없이 I2C로 직접 읽습니다.
- `mpuInit()` : 0x6B(PWR_MGMT_1) 레지스터에 0을 써서 절전 모드를 해제합니다.
- `mpuRead()` : 0x3B부터 14바이트를 한 번에 읽습니다. (가속도 6 + 온도 2 + 자이로 6바이트)
  - 가속도 ÷ 16384 → g 단위 (±2g 범위)
  - 자이로 ÷ 131 → °/s 단위 (±250°/s 범위)
  - 온도 값은 사용하지 않아 건너뜁니다.

**④ 요청 처리 (주소 목록)**

| 주소 | 하는 일 | 응답 |
|---|---|---|
| `/` | 사이트 화면 보내기 | HTML |
| `/rgb?c=r` `g` `y` `off` | LED 색 바꾸기 | `RGB → 빨강` 등 |
| `/beep` | 부저 0.3초 울리기 | `부저 울림` |
| `/mpu` | MPU6050 값 읽기 | JSON |

`/mpu` 응답 예시:
```json
{"ok":true,"ax":0.01,"ay":-0.02,"az":1.00,"gx":0.3,"gy":-1.2,"gz":0.5}
```
읽기에 실패하면 `{"ok":false}`를 보내고, 다음 요청 때 MPU 연결을 다시 시도합니다.

**⑤ `setup()`에서 신경 쓴 부분**
- 시작할 때 LED와 부저 핀을 모두 LOW로 두어 전원을 켜자마자 소리가 나거나 불이 켜지지 않게 했습니다.
- `Wire.setTimeOut(50)` : MPU 선이 빠져도 I2C 통신이 오래 멈추지 않아 사이트가 계속 작동합니다.
- `WiFi.setTxPower(WIFI_POWER_8_5dBm)` : 와이파이 송신 세기를 낮춰서 배터리로 작동할 때 순간 전류 때문에 ESP32가 리셋되는 것을 막습니다.

## 6. 문제 해결

| 증상 | 확인할 것 |
|---|---|
